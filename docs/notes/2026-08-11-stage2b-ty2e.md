# Stage 2B: synthesized expression results

TY-2E keeps the original handwritten recursive-descent parser, but separates
grammar success from expression type success. `token_and_status::valid_parse`
now means syntax consumed successfully; `semantic_valid` says whether the
expression has a usable type. The `resolved_token` on a successful expression
is a synthetic `T_IDENTIFIER` with an exact primitive `identifier_data_type`.
It is not a declaration, is never stored in a scope, and exists only to carry
the result type and source anchor to an enclosing parser production.

The parser now left-folds factor, term, relation, arithmetic, and logical
layers. The Typechecker owns the non-streaming unary/binary type matrix and
returns a fresh synthetic result for every successful fold. It never reads or
writes the old `first_token`, `second_token`, or `relation_tokens` accumulator.
That accumulator remains compiled but has no expression-parser call sites.

The 2024 grammar's unusual precedence is retained: relations bind inside the
right operand of `+`/`-`, a single leading `not` applies to its full initial
arithOp, and `&`/`|` share a left-folded level. Prefix/double/trailing operator
recovery remains grammar-owned; semantic failures suppress only their current
statement and continue consuming syntax.

This slice deliberately leaves assignment compatibility (SIL-2), loop-specific
checking (TY-6), arrays (TY-8), and removal of the legacy compatibility matrix
for later focused changes. Procedure arity/signature validation (SIL-1) is now
the following focused Stage 2C slice.
